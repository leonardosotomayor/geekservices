From Artificial Intelligence to Generative AI: Explained

AI, machine learning, deep learning, and generative AI get used interchangeably, but they describe different, nested ideas. Here is how they fit together, using a coding assistant like Claude Code as the running example.

This started as a paper I wrote for one of my classes. I'm sharing an adapted version of it here because the same distinctions come up constantly with clients trying to decide what "AI" actually means for their business.

1. Introduction and Definition

In practical terms, artificial intelligence (AI) refers to computer systems designed to perform tasks that normally require human judgment, such as recognizing patterns, making predictions, or generating recommendations from data. The National Institute of Standards and Technology frames this more formally: AI systems are engineered, machine-based systems that produce outputs such as predictions, recommendations, or decisions based on defined objectives (Tabassi, 2023). In other words, an AI system pursues a goal set in advance by processing data through mathematical rules rather than by reasoning the way a person does. Human thinking draws on lived experience, emotion, and intuition; AI systems instead find statistical patterns in the data they were trained on and apply those patterns to new inputs, without the consciousness people bring to understanding meaning.

A coding assistant illustrates this well: it reads a request or a piece of code and returns a suggestion without understanding it the way a human programmer would. Coding assistants sit at the narrow end of a hierarchy that runs from AI as the broad field, through machine learning and deep learning, into generative AI and large language models (LLMs), the deep-learning models built mainly for language and, by extension, code.

2. The Relationship Among AI, Machine Learning, Deep Learning, GenAI, and LLMs

The five terms form nested categories that move from broad to narrow (Taulli, 2019). Artificial intelligence is the broadest field, covering any system built to perform tasks that would normally require human intelligence. Machine learning is one approach within AI: instead of programming every rule by hand, a machine-learning system learns patterns directly from data. Deep learning narrows this further to methods using neural networks with many layers, letting a model build increasingly abstract representations of raw data such as pixels, sound, or text (LeCun, Bengio, & Hinton, 2015).

Generative AI describes systems that create new content rather than simply classify or predict a fixed answer; Goodfellow et al. (2014) helped establish this idea with generative adversarial networks, which learn to produce realistic synthetic data by training two networks against each other. Large language models are deep-learning models trained on huge amounts of text that predict the most likely next word or token given what came before (Brown et al., 2020), and code-generating systems such as Claude Code apply this same approach to programming languages. Not every LLM counts as generative AI, and not every generative AI system is an LLM; many LLMs are generative simply because producing new text or code is their central task.

4. Claude Code as the Central Example

Claude Code is a command-line tool built on Anthropic's language models that lets a developer work with an AI assistant directly inside a terminal and a codebase, rather than through a separate chat window. According to Anthropic's documentation, it can take natural-language instructions and turn them into concrete actions: inspecting a codebase to build context, explaining unfamiliar code, proposing or making changes to source files, helping track down bugs, and, with the developer's permission, running development commands such as builds or test suites (Anthropic, n.d.). These are documented product capabilities, not independent proof that the tool performs well in every setting. In practice, a tool like this can speed up routine work and help a newer developer get oriented in a large codebase faster, but giving it permission to read files and run commands also carries risk: it can misread intent, generate code that looks right but is subtly wrong, or run a command with unintended side effects, so a human developer still needs to review its output before trusting it in a production system.

What makes this possible is the model underneath Claude Code. It is trained on huge collections of text and code, learning statistical relationships among tokens, the small units, such as words or fragments of code, that make up its input and output (Brown et al., 2020), aided by the Transformer architecture, whose attention mechanism weighs how relevant different parts of a sequence are when predicting what comes next (Vaswani et al., 2017). Given a prompt, the model does not look up a stored answer; it predicts the single most likely next token, then repeats that step many times, treating its own output as new context, until a full response is assembled. Next-token prediction is the mechanism; code generation is the resulting activity, and the model does not think like a programmer or understand code the way a person does. Chen et al. (2021) showed the limits of this directly: their Codex model produced a fully correct solution on the first try for well under half of a set of hand-written programming problems, improving substantially only when it was allowed many attempts per problem, a reminder that generated code still needs to be read, run, and tested by a person before it can be trusted.

5. Comparison Table

These differences reflect distinctions described in research on deep learning, language models, and generative systems (mainly based on the readings of Goodfellow et al., 2014; LeCun et al., 2015; Vaswani et al., 2017).

Comparison of machine learning, deep learning, and generative AI
Criterion Machine Learning Deep Learning Generative AI
Definition Identifies patterns in data and uses them to make predictions, classifications, recommendations, or decisions. Uses neural networks with multiple processing layers to learn increasingly complex representations from data. Produces new content, including text, code, images, audio, or video, from patterns learned during training.
Data requirements Vary according to the algorithm, task, and quality of the available data. Often benefits from large datasets containing complex or unstructured information. Requires representative data suited to the content it is designed to create.
Feature engineering Traditional machine learning often relies on humans to select and transform useful features. Models can learn many useful features automatically from raw or minimally processed data. Systems learn internal representations that allow them to produce outputs from prompts or other conditions.
Hardware requirements Many tasks can run on CPUs, although GPUs may improve performance. Training large models often benefits from GPUs or specialized accelerators. Large models may require substantial computing resources during training and deployment.
Training time Varies according to the algorithm, dataset, and hardware. Often takes longer to train because models contain many learned parameters. Varies substantially according to model size, dataset complexity, and computing resources.
Interpretability Varies depending on the model and the complexity of the task. Decisions can be difficult to interpret because they involve many learned parameters. Outputs may be difficult to trace to specific training examples or internal processes.
Advantages Can support predictions and decisions across many practical applications. Can learn complex representations from text, images, audio, and code. Can produce useful drafts, explanations, code, and other content quickly.
Disadvantages Performance depends on data quality, model selection, and appropriate evaluation. Can require substantial data, computing power, and technical expertise. May produce inaccurate, biased, insecure, or misleading outputs.
Common applications Fraud detection, recommendation systems, classification, and forecasting. Image recognition, speech recognition, language processing, and code analysis. Chatbots, coding assistants, image generation, text generation, and synthetic media.

6. Discussion: Why Deep Learning Enabled GenAI

The rise of generative AI tools for coding followed several developments in deep learning that built on one another. Deep-learning models learn complex representations automatically, discovering useful features from raw text or code instead of relying on hand-designed rules (LeCun, Bengio, & Hinton, 2015), which let a single architecture apply to many kinds of data, including programming languages. Growing datasets of natural language and source code gave models far more examples to learn from. The Transformer architecture improved how models process sequences, letting them weigh relationships between distant parts of a sequence while running in parallel on modern hardware, which made training much larger models practical (Vaswani et al., 2017). Rising computing power, especially GPUs and specialized accelerators, made training these larger models on larger datasets feasible. As language models scaled up, they grew better at responding to instructions and to a small number of examples without retraining, sometimes called few-shot behavior (Brown et al., 2020).

Together, these developments are what let a tool such as Claude Code read an instruction and generate or modify code that is often useful. Claude Code is not the only such product: GitHub Copilot offers similar suggestions inside a code editor (GitHub, n.d.), and Google's Gemini Code Assist offers comparable code completion and chat support (Google, n.d.), which suggests this is a general capability made possible by deep learning rather than a result specific to one product. All in all, deep learning made coding assistants more capable, but it did not make them automatically reliable. Human developers must still inspect generated code and test it before relying on it in a real project.
